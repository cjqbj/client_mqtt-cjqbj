# AGENTS.md

## 铁律：边缘功能绝不阻塞主流程

本项目的核心是 MQTT/HTTP RPC 主流程。`global_topic_list`（监听 topic 定期报告）、
`global_topic_url_list`（远端上报）、`stats_*`（连接质量统计）等都属于**边缘统计/附加
功能**，它们出任何问题都只允许**降级**，不允许影响启动与主流程。

具体要求：

1. **默认值兜底**：每个配置键在代码里都必须有默认值；配置缺失、类型写错、旧键残留、
   整份 `rpc.json` 损坏，都逐项回落默认值并只打 WARNING，绝不抛异常打断启动。
2. **故障隔离**：一项配置坏掉只回落该项。例如 `global_topic_url_list` 写错，不得牵连
   `stats_ping_interval`、`global_topic_list_interval`，更不得牵连 broker/topic/公钥。
3. **默认值本身也要防错**：打包/代码里的默认值写错（如模板被写成嵌套 list）属于 bug，
   但运行期只降级（如关闭远端上报），不崩溃——这是手机端 `start()` 崩溃的真实教训。
4. **显式输入才严格**：只有用户当场给的输入（`rpc_config(...)` 热更新、命令行参数、
   构造参数）才立即报错；文件内容与运行时合并一律容错。
5. **测试必须覆盖容错**：任何配置读取/校验改动，都要补"脏数据不影响主流程"的用例
   （坏 JSON、坏类型、坏默认值、单键坏不连坐），见
   `tests/test_server_mqtt_config.py`。
6. **`global_topic_url_list` 语义**：只有显式读到或设置空数组 `[]` 才关闭远端上报；
   同一数组里个别 URL 非法只跳过该条（不影响同组其它 URL）；整组全非法或不是数组
   都回落代码默认值（默认值本身坏才关闭）。该报告常开，没有 `enable_global_topic_list`
   开关。
